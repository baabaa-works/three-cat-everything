# 卡點微調計畫（給執行 session，Opus 5.5）

只改剪輯點與時間軸，讓小貓舞步、剪接、字幕都對上音樂。字幕文字、版面、片尾卡內容、裁切範圍都不動。SPEC.md 的驗收標準全部仍然適用。

## 為什麼現在沒卡點

- 音樂就是 `cats.webm` 自己的音軌（11.81 秒一圈），所以「小貓循環相位 = 音樂相位」時舞步必然對拍。現在的音樂從時間軸 0 秒直接鋪，沒有對齊錄影裡小貓的循環相位。
- 每個剪接點都讓小貓的相位跳一次，而剪接點（6.0 / 7.5 / 9.0 / 11.0 / 13.0）和字幕切換點都不在拍點上。
- 拖曳＋滾輪那段是 2 倍速，舞步速度直接變兩倍。
- 第二組小貓是按下「再來一組」那一刻才開始播，和第一組的相位差是隨機的。
- 片尾卡的 `cats.webm` 從 0 開始播，但那時音樂在第 8.19 秒的位置。

## 已量到的數字

- 音樂 145.6 BPM，一拍約 0.41 秒，四拍一小節約 1.64 秒。
- 音樂維持從時間軸 0 秒開始（不加偏移），第二圈從 11.81 秒接上。
- 小節線（時間軸秒數）：0.025、1.605、3.255、4.895、6.555、8.195、9.855、11.495、**11.835（循環接縫）**、13.415、15.055、16.705、18.365、20.005、21.655、23.305。
- 接縫前最後一拍只有 0.34 秒（一圈 11.81 秒不是整數拍），所以「差整數拍」的對法不能跨接縫。
- 完整拍點表：`npx hyperframes beats assets/music.m4a --json`（在 `promo/` 下跑）。

## 新時間軸

所有剪接點與字幕切換點都落在小節線上。來源時間是 `raw/promo/take1.mp4`、`take2.mp4` 的秒數，「約」的數字由執行時依相位微調（±0.2 秒內）。

| 時間軸 | 字幕 | 畫面 | 來源 |
|---|---|---|---|
| 0 – 3.255 | 1 | 純 K 線 | take1 約 4.9 起 |
| 3.255 – 6.555 | 2 | 小貓在拍點上出現（硬切）、鏡頭右移 | take1 小貓已顯示、尚未拖曳的區間（約 8.3–15.5 之間取 3.3 秒） |
| 6.555 – 8.195 | 3a | 拖到 K 線中央，原速 | take1 約 15.8 起 |
| 8.195 – 9.855 | 3a | 滾輪放大，**原速，不再 2 倍速** | take1 約 21.0 起 |

根合成的鏡頭平移、推近、片尾變暗的起點跟著移到對應的小節線。

## 相位怎麼對

1. **量出錄影裡第一組小貓的循環起點。** 在 take1、take2 各找一格和 `cats.webm` 某一格姿勢完全相同的畫面，換算出「來源時間 s 對應循環相位 (s − s0) mod 11.81」。建議先用每格畫面差異量做交叉相關找候選，再用逐格截圖比對確認到 ±1 格。
2. **最後一長段（13.415 起，含片尾暗底）要完全同步。** 入點選在第一組相位 = 1.605 秒的那一格（13.415 mod 11.81）。take2 有 25 秒，需要 10.1 秒，一定找得到。
3. **前面的短段只要求差整數拍。** 每段入點在 ±0.2 秒內微調，讓「小貓相位 − 音樂相位」是 0.41 秒的整數倍。若該段內小貓或音樂會跨過循環接縫，就把入點挪一拍避開。
4. **片尾卡的 `cats.webm`** 加 `data-media-start="8.195"`，和音樂完全同步（8.195 + 3.495 < 11.81，不會跨圈）。

## 第二組小貓

先量 take2 裡第二組相對第一組的相位差。

- 差在整數拍 ±2 格內：直接用 take2。
- 否則重錄最後一段：從系統匣「結束」app 再重新啟動，兩組視窗會同時載入，相位幾乎一致；確認兩組都在、位置還在 K 線上後，用同一條 `ddagrab` 指令錄 15 秒成 `raw/promo/take3.mp4`，量過相位差合格才採用。重錄時副螢幕要還是 TradingView 國巨畫面，底部廣告彈窗維持裁在畫面外。
- 重啟後兩組仍差超過 2 格：以第一組（畫面中央、較大的那組）為準，並在回報裡說明。
